# Лабораторна робота: вступ до мікросервісів

## Мета роботи

Метою роботи було перетворити Helpdesk-застосунок на багатомодульний Maven-проєкт і розділити його функціональність на окремі сервіси. Після змін система складається з сервісу заявок, сервісу користувачів та сервісу сповіщень.

## Структура проєкту

Кореневий `pom.xml` налаштований як Maven aggregator (`packaging` зі значенням `pom`) і містить модулі:

- `helpdesk-system` — керування заявками та категоріями;
- `user-service` — зберігання та керування користувачами;
- `notification-service` — обробка запитів на сповіщення та інші операції після створення заявки.

Кожен модуль має власний `pom.xml`, головний клас Spring Boot, конфігурацію, тести та Dockerfile. Модулі збираються в межах одного Maven reactor, але не використовують код інших сервісів як Maven-залежність.

## Розділення сервісів

`helpdesk-system` працює на порту `8081`, `user-service` — на `8082`, `notification-service` — на `8083`. Сервіси взаємодіють через HTTP API.

Користувачі зберігаються у базі даних, якою володіє `user-service`. У сервісі заявок сутність `Ticket` зберігає `createdById` і `assignedToId` як ідентифікатори, а не як JPA-зв’язки з таблицею користувачів. Коли Helpdesk потрібне ім’я автора або виконавця, він звертається до внутрішнього API `user-service`.

Локальне керування користувачами в Helpdesk прибране. Користувачами керують через REST API `user-service`; його основні CRUD-маршрути доступні адміністраторам.

## Взаємодія із сервісом сповіщень

Після створення заявки Helpdesk асинхронно надсилає до `notification-service` запити на сповіщення про створення заявки, формування PDF та повідомлення виконавця. Для HTTP-взаємодії використовується `RestClient`.

Асинхронний координатор збирає результати операцій і обробляє помилки або тайм-аути окремо для кожної з них. Збій сповіщення не скасовує створення заявки. Наразі зовнішні ефекти в `notification-service` імітуються та відображаються в логах — реальне надсилання листів, створення PDF і виклик webhook можна реалізувати окремо.

## Дані та міграції

У Helpdesk залишається база для заявок і категорій, а `user-service` використовує окрему базу для користувачів. Liquibase керує схемами баз даних.

Під час відокремлення користувачів у таблиці заявок поля з ID автора та виконавця збережені, але зовнішні ключі до локальної таблиці користувачів прибрані. Користувачів перенесено до бази `user-service` зі збереженням їхніх ID, щоб посилання у наявних заявках залишилися правильними. Локальну таблицю користувачів у Helpdesk видалено окремою Liquibase-міграцією.

## Безпека

Внутрішні API `user-service` та `notification-service` захищені токеном у заголовку `X-Internal-Token`. Значення токенів і паролів передаються через змінні середовища та локальний `.env`, який не слід додавати до Git.

Для автентифікації користувачів збережено інтеграцію з Keycloak. Авторизовані маршрути API перевіряють JWT та ролі користувачів.

## Docker та запуск

Для кожного сервісу створено окремий Dockerfile. Docker Compose запускає три сервіси, PostgreSQL для Helpdesk і User Service та Keycloak. Адреси сервісів у контейнерах задаються через імена сервісів Compose.

Основні команди з кореня проєкту:

```powershell
docker compose up -d --build
docker compose ps
docker compose logs -f helpdesk-system user-service notification-service
```

## Тести та перевірка

Тести зберігаються у `src/test/java` відповідних модулів і перевіряють REST-контролери, логіку сервісів та пов’язані сценарії застосунків.

Загальну збірку та тести всіх модулів можна запустити з кореня проєкту:

```powershell
mvn clean verify
```

Дерево залежностей кожного сервісу можна перевірити окремо командою Maven `dependency:tree`. Це дає змогу переконатися, що сервіси не залежать один від одного як від Maven-модулів.

## Висновок

У результаті Helpdesk було організовано як багатомодульний проєкт із трьома окремими сервісами. Користувачі та сповіщення відокремлені від основного сервісу заявок, взаємодія між сервісами відбувається через HTTP, а запуск компонентів і баз даних автоматизовано за допомогою Docker Compose.
